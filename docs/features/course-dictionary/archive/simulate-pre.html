What a trace is

A trace is one sign that the learner spent real time with one part of a page. A page is read only when every part has one.

Card page · step dots

Page not read
Traced parts stay traced; leaving and coming back resumes.

How each part earns its trace

Locked. A number can still move if it proves wrong in use.

Text

Counts once it has been on screen long enough to read: one second per ten words, at least five seconds. Hearing it read to the end counts too.

Picture

Counts once it has been on screen for three seconds, or at once when the learner taps it to enlarge: the tap is deliberate. A look alone is the weakest trace, so a page that holds only a picture rests on it alone.

Video and voice

Video counts at eighty percent played. The speaker counts only when it reaches the end. Pausing or leaving keeps what already played.

What this proves, and what it does not.

These traces live on the learner's device with the pack. Anything on a learner's own machine can be edited, so a trace is a hint, not proof. It feeds "Pages read" only: it never raises a score, never unlocks anything, and never blocks an answer. A short page still needs its five seconds; the speaker and the video are the strongest traces because they measure time that was actually played.

Locked. Next: whether pages travel in an exported pack and the full backup.

Pictures and videos

Two kinds of media: kept in the browser, or linked

Videos make the browser store heavy. Google as the store would break offline study and whole backups. This shape keeps both: a page may hold a file, or an address.

Kept in the browser

The file itself lives with the pack, on this device.

Offline
  • Size: a picture up to 1 MB, shrunk to 1600 pixels; a video up to 20 MB.
  • Phones and tablets: pictures may be kept; a video must be linked, never kept.
  • Total: every kept file, across every pack, counts towards one 300 MB cap.
  • Offline: shows and plays with no connection.
  • Travels: inside a shared pack zip and inside the full backup.
  • Room: a meter shows kept MB against the cap. A save that would pass 300 MB is refused: link it instead, or remove a kept file. Free space is checked too.

Linked · online

YouTube, a Drive file, or any address. The file stays where it is.

Needs a connection
  • Size: none on this device; the page holds only the address.
  • Offline: the part shows a note and the address instead of the file.
  • Travels: the address goes with the page; the file does not. A shared pack still needs a connection.
  • Backup: the address is saved, the file is not. A file the author deletes leaves a “gone” note, not a broken page.

When the author adds it

The same two buttons for a picture or a video. The kind is chosen once, and the page says it ever after.

A file

On a phone or tablet, this path takes pictures only. A video there must be linked: choosing a video file is refused. A touch-screen laptop is treated as a computer.

What this leaves out, on purpose.

No Google login. A learner's files never leave their device unless the learner pastes an address. YouTube is a source of videos, not the place a course is saved. That keeps the app offline-first, keeps a backup whole, and avoids a sign-in that would expire about every hour.

This would be the rule: every picture and video says which kind it is, on the page and in the Course Builder. Confirm it, or change a line.

What this is asking

  1. Card page structure. B was chosen: one part at a time, stepped. A is gone.
  2. Pack and deck pages. They do not exist in the app today. This feature adds them: a page for the course and a page for each deck, with the card pages under them.
  3. Speaker. Every text part carries a speaker icon that reads that part aloud. Pictures and videos have none.
  4. Access. The card page opens from both places: the library card row and the study card. Pack and deck pages open from the up-right arrow on their row in the Study dropdown. Both questions on screen 5 are settled.
  5. Course rule. Reading is never locked and never blocks an attempt. On screen 2 the rule is one chip on the card: icon only when narrow, icon with words when wide. Pressing it opens the page; the page earns its read mark when every part is traced, and answering first shows a warning and still counts.
  6. Hint and Dictionary. Same icon rule: icon only when narrow, icon with the word when wide. Plain bordered buttons; the sticker drawings were dropped. The chip and both buttons use an 8px corner, not a pill.
  7. Private changes. The “Your copy” badge marks a built-in course edited by one learner. Correct?
  8. The word. “Lesson” is not used anywhere here; “read in order” is the placeholder. The name is still open.
  9. Media kinds and caps. Locked (entries 23-28): a file kept in the browser, or an address linked online (YouTube, Drive, any URL). A kept video stays under 20 MB and all kept media together stay under 300 MB; linked media has no cap. On a phone or tablet a video must be linked; only pictures may be kept (a touch-screen laptop counts as a computer). No Google login: the app never stores a learner's files on Google.

Already locked: per-card order, upward navigation, no gating, a short teaching layer that links to the page, shared Authoring, both edit routes, and private personal changes.
