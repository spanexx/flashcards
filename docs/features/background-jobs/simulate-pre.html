Generation and import keep working

The learner presses once, can leave Create, sees live state in a global Jobs control, and gets a completion notice with a way back to the affected pack or deck.

1

Generation continues after leaving Create

The job belongs to the page, not the panel. The learner can read Packs while it runs.

Generate 5 cards · New pack
Subject: ordering coffee · Focus: cafes, paying · Mixed styles
The prompt was approved. It leaves only when you press Send.
After Send, Create is free. The Jobs control shows the state from any screen.

What the learner sees

1Queued behind any older ready job.
2Asking the provider. Live label in the Jobs control.
3Validation and the all-or-nothing import.
4Completion notice with View → the new pack.

No modal. No blocked Create screen. A failure is a notice and a Try again row.

2

Timeout waits one minute, then tries again

Only “The provider took too long to answer.” is retried. One initial try plus three retries.

After the last retry

The row becomes Failed. The panel keeps the exact provider sentence and offers Try again. A manual Try again starts a fresh four-try budget.

Not retried: rejected key, unreachable address, HTTP error, empty answer, invalid batch, invalid import.

4

A bad import fails honestly

Validation errors are not retried and nothing is written.

Failed job

Importing cards
Starter → Basics · file
Failed
Nothing was imported, because the file needs fixing.
cards[2].answerDef: expected a cloze answer

Why no retry?

A malformed file will stay malformed. Retrying would hide the error for another minute. The learner fixes the file and presses Try again only when they choose.

The old library is untouched. The all-or-nothing importer is still the only writer.
5

A reload does not pretend to resume

Queued jobs and future retries resume. A running provider call becomes an interrupted failure.

A queued job would resume with its stored prompt. A waiting retry keeps its original minute.
