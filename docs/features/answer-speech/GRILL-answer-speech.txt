--------------------------------------------------------------------------------
Q1. What is spoken?
A. [Amended by Q7, 2026-10-27: the answer is read as per-language lines, not
   one utterance.] The whole answer side: text parts in display order,
   including a translation part (the learner hears the whole answer)
   [agent decision]. Blank parts and media are skipped (there is nothing to
   say). A speak part is read as part of the answer [agent decision].
   Why: the learner said "listen to it" about the answer that is shown.
   Rules out: speaking the prompt, the summary, the hint or the regions.
   Source: ticket answer-speech.md Q1; `v1/src/app/study/StudyCard.tsx:231-234`.

Q2. Which language and which voice?
A. [Amended by Q7, 2026-10-27: a part's own language tag decides its voice;
   per-part voice switching is now required, because one answer can hold a
   Polish line and an English translation.] The pack's learning language
   (`PackStatus.language`) was the utterance language, so numbers are read in
   that language too; when the pack has no language, no `lang` is set and the
   device chooses its default [agent decision]. The device voice is used; no
   new audio files, no network call, no provider.
   Why: the learner named Polish as the example and said numbers follow.
   Rules out: always-English, recorded audio.
   Source: ticket Q2; `v1/src/app/StudyClient.tsx:780-782`,
   `v1/src/lib/client/speech.ts:8`.

Q3. What happens with a code answer?
A. Raw code is never read aloud. When the card has teaching text, that text is
   spoken as the explanation [agent decision: all teaching text parts, in
   order]. When it has none, one short line says this answer is code and to
   read it on screen. Text parts beside the code are still spoken.
   Why: the learner said "don't read the code symbols, give some kind of
   explanation of it".
   Rules out: reading braces and semicolons, staying silent with no cue.
   Source: ticket Q3; `v1/src/lib/shared/types.ts:27-34`.

Q4. Where is the control, and what does it look like?
A. In the answer section, directly under the rendered answer, a normal small
   button labelled "Hear the answer". It is a button, never autoplay, and it
   cancels any speech already running before it speaks.
   Why: the learner placed it in the answer section; surprising audio is worse
   than no audio.
   Rules out: a floating player, autoplay on reveal, a second card screen.
   Source: ticket Q4; `v1/src/app/study/CardSide.tsx:66-73` (existing pattern).

Q5. What if the device has no voice?
A. The button is not rendered. The check runs after mount, like the teaching
   layer, so the static build does not disagree with the browser
   [agent decision].
   Why: a control that does nothing is a bug the learner cannot diagnose.
   Rules out: a dead button, an error dialog.
   Source: `v1/src/app/study/TeachingLayer.tsx:16-36`.

Q6. What must not change?
A. The existing "Hear it" speak part, the listening card's "Play the line",
   the teaching layer's "Listen to the layer", and the feedback cues stay as
   they are. The answer control is additive.
   Why: the learner explicitly separated the answer voice from the chime.
   Rules out: replacing any current sound or speech control.
   Source: learner clarification; `v1/src/lib/client/sound.ts:1-8`.

Q7. How does the app know which language a word is? (added 2026-10-27)
A. The card says it. Every text part carries a language tag written when the
   card is created, from the pack's declared pair: a full line is tagged with
   the learning language, a translation with the question language, and any
   other text with the language it is written in. Speech reads each tagged
   part with that language; neighbouring parts with the same language are
   joined into one utterance. Cards written before tags existed fall back to
   the pack pair (translation -> `sourceLanguage`, everything else ->
   `language`), so older packs still play.
   Why: the learner heard the English translation "I was at home." read with
   the Polish voice, and said each language must keep its own voice (Polish
   for Polish, Spanish for Spanish, Portuguese for Portuguese). The pack pair
   alone cannot describe a mixed-language answer, and guessing per word is
   not reliable.
   Rules out: one voice for the whole answer; guessing the language at speak
   time; hard-coding Polish/English; silently mispronouncing a translation.
   Source: learner report and clarification 2026-10-27; card creation
   `v1/src/lib/provider/generate.ts:130-203`,
   `v1/src/lib/browser/authoring.ts:61-103`; schema
   `v1/src/lib/core/schema.ts:10-16`.
