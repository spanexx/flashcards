2

Install from the top right

The browser prompt when it exists; a plain hint when it does not.

The control

Fixed at the top right on every screen.
Use the browser menu or Share → Add to Home Screen.

The manifest

  • name: Flashcards
  • display: standalone
  • start_url and scope: ./
  • 192 any, 512 any, 512 maskable

States

Prompt ready: clicking opens the browser install dialog.
No prompt: clicking shows the manual hint.
Installed: the button disappears.
Standalone: CSS hides the button.
The button is never the only route; the browser menu still works.
3

The shell opens without the network

One online visit fills a scoped cache. A reload then renders the app.

Worker behaviour

  • Install precaches every route, page payload, icon, pack and hashed asset.
  • Navigation: network first, then cache, then the shell, then a plain 503.
  • Other same-origin GETs: cache first.
  • Cache name: flashcards:<scope>:<hash>.
  • A new worker waits; it does not delete assets under an open page.

Rehearsal

Online: the seeded plan appears and the worker reports 49 cached files.
Offline: reload still shows "Today's session" and the shell.
First visit offline: the browser's own offline page. The app cannot cache before it has been fetched once.
4

A checked Pages deploy

The build refuses an export that would break at /flashcards/.

Pipeline

  1. Checkout and Node 22.
  2. npm ci in v1/.
  3. Typecheck, lint, build with NEXT_PUBLIC_BASE_PATH=/flashcards.
  4. Full test suite.
  5. check:pwa on v1/out.
  6. Upload the artifact and deploy with Pages.
  7. Curl the live page, manifest and worker.

The hard gate

Routes, 404 page and built assets exist.
Manifest fields and exact PNG pixel sizes.
Every local link is under the base path and exists.
Worker handlers, scoped cache, relative precache.
Every _next/static asset is precached.
